# 진도판

2027년 변리사 1차 학습 진도 대시보드. 정적 페이지 하나로 동작한다.

**→ https://dangchame.github.io/study-plan/**

## 무엇인가

계획 계산 로직이 페이지 안에 들어 있다. 진도(강수·페이지)를 입력하면
증량 램프 · 회독 6주 주기 · 하루 총합이 브라우저에서 다시 계산된다.
서버도 빌드도 없다.

## 파일

| 파일 | 역할 |
|------|------|
| `index.html` | 배포본. 이 파일 하나가 사이트 전부다 |
| `plan.tpl.html` | 원본 템플릿. `/*INVENTORY*/` 자리에 강의 데이터가 들어간다 |
| `lectures.json` | 13개 강좌 372강의 강별 시간·예습 단가 |
| `progress.json` | 배포 시점의 진도 (강수·페이지) |
| `build.py` | 위 셋을 합쳐 `index.html`을 만든다 |

## 진도가 정해지는 방식

**주소창에 `dangchame.github.io/study-plan` 만 쳐도 항상 최신이 나온다.**

세 군데에서 진도를 읽어 **가장 나중 것**을 쓴다:

| 출처 | 갱신 시점 |
|------|----------|
| **사이트 배포본** (`progress.json`) | 계획을 다시 짜서 배포할 때 |
| **이 브라우저** (localStorage) | 사이트에서 진도를 올렸을 때 |
| **URL 해시** | 「이 진도로 링크 복사」로 받은 주소를 열었을 때 |

화면 맨 아래에 `진도 기준 2026-09-17 · 사이트` 처럼 **어느 쪽이 쓰였는지** 표시된다.
브라우저에 남은 값이 이상하면 **「사이트 기준으로 되돌리기」** 를 누르면 된다.

## 다시 빌드하기

`progress.json`에 최신 진도를 적고:

```
python3 build.py
```

`plan.tpl.html`의 자리표시자에 **강의 인벤토리 · 진도 · 배포 시각**을 채워
`index.html`(Pages용)과 `plan.html`(Artifact용)을 만든다.
배포 시각이 새로 찍히므로, 배포하면 브라우저에 저장된 옛 진도보다 **최신이 되어 이긴다**.

## 계산 규칙

- 주 5일(월-금) 공부 + 2일 휴식
- 강의는 2배속. −5분 보정은 민사소송법 한정
- 예습: 화학 기출·객관식 20분/강(실측) · 물리 기출 30분/강(가정) · 생물·지구 10분/강
- 교재: **민법연습장** 3-275p · **특허연습장** 2-362p (둘 다 해설 없이 문제만)
- 회독 속도: 민법연습장 **6p/h** · 특허연습장 **15p/h** (보수적으로 내려 잡은 값)
  - 연습장은 구 교재에서 **해설만 뺀 판**이라 총 소요 시간이 보존된다 → 압축비 환산은 6.7 · 17.2
- 하루 **가용시간**을 먼저 정하고, 회독을 가용시간에 **비례 배분**한 뒤, 강의가 나머지를 먹는다
- 특이 일정: 10/22·10/26·10/27 공부 못 함
- 9/11-9/15 미실시 → 완강일·회독완료일을 **1주씩 뒤로** 밀었다 (하루 4-6시간)
- 공휴일은 무시한다
